# Guest response, recovery and post-match flow — 1.10

The host previously rejected every control frame more than 240 sequence numbers ahead of the last received frame. A delayed first packet or a two-second uplink interruption could therefore permanently lock out guest movement even while snapshots and pings arrived normally. Valid increasing counters now resynchronize independently of gap size. Processing is still bounded to 16 frames per packet, and only the newest held controls are consumed; up to two queued jump edges survive a short press/release burst. A 300 ms input timeout releases held controls.

Guest prediction now includes the ball and local car/ball and car/car contacts on separate predicted bodies. Authoritative scores, touches, demolitions and simulation state remain host-owned. Remote cars interpolate, while the ball and local car receive responsive predicted poses followed by authoritative correction. Correction replays are capped at 48 frames instead of 120, and input packets use four compact redundant frames instead of sixteen verbose objects. No peer submits its own positions or goals. Prediction improves response but cannot remove real network latency or guarantee exact collision agreement.

After an established connection drops, physics and the clock freeze while the same players reconnect for up to 20 seconds. A per-session random 256-bit secret identifies a recovery queue. New transports preserve the original gameplay roles regardless of signaling initiator. Resume messages verify secret, build, role and match ID, then exchange a reliable authoritative snapshot, reset both input counters and interpolation state, and acknowledge readiness before resuming. Host pause state is preserved. Pending rematch starts are reconciled if the guest prepared before its start acknowledgement was lost. Failed sends retry without unfreezing the host. Late callbacks and handshakes at/after the deadline cannot resume a retired match.

The connection attempt watchdog permits up to 18 seconds within the absolute 20-second window. An earlier eight-second attempt limit failed a real-peer test because broker pairing and software ICE gathering took longer; it was corrected before release. Intentional Leave and Find Next end the old room. Recovery requires the existing page and host to remain open: it is not host migration, recovery after refresh, or a new-player rejoin system.

At full time, either player may request or cancel a rematch. Both players must agree before the host starts one fresh match. Find Next Match retires the old session and starts a new 60-second search; the other player keeps their results and can choose independently.

Network preferences appear in Online Match and Options → Network and persist locally. Worldwide, Americas, Europe, Asia, Oceania and Middle East / Africa are separate exact-match queues. These are user-selected groups, not measured player geography or dedicated regional servers. Maximum ping may be 100, 150, 200 (default), 300 ms or unrestricted. Three verified round trips must meet both players' limits before automatic readiness. Rejection/retry retains the original search deadline.

The HUD shows measured peer ping and estimated missing realtime updates. A successful-send sequence counts realtime datagrams independently of physics/input/snapshot counters; a 256-packet window permits eight packets of reordering and needs 20 settled samples before reporting loss. Reliable pings exchange each receiver's loss estimate. High ping, jitter, update loss and a complete update stall have distinct warnings. Gameplay traffic age is tracked separately from reliable ping replies, so a dead realtime channel cannot appear healthy merely because pings work.

The mouse button chord now tracks individual mouse down/up events and the authoritative release button mask. Steering matches left/right on screen, controller look springs back after right-stick release, and holding opposing pitch cancels the pitch component of a directional flip. Existing keyboard aliases and ball-camera lock are retained.

## Verification

Version 1.10.0 passes 163 automated tests. New cases reproduce delayed first input at frame 480, a four-second uplink outage, immediate predicted contacts without changing authority, bounded correction work, a 256 kbps constrained uplink with 300 ms one-way delay, mouse chord release and flip cancellation. Recovery cases include reversed signaling roles, asymmetric detection, slow negotiation, exact deadlines, wrong identity, failed final sends and interruption during rematch start. UI checks cover consent, next-match actions, saved preferences and stale realtime data despite healthy reliable replies.

The optional `scripts/check-live-recovery.mjs` uses public signaling and actual WebRTC peers, with same-container host ICE candidates. It checks automatic pairing/ping admission, state preservation, fresh input acknowledgements after recovery, paused recovery, mutual rematch and Find Next departure. It does not verify browser GPU rendering or separate-home-network NAT/TURN traversal. No browser or system packages were installed, and no changes were made on the user's PC.

The final live run recovered in 13.511 seconds, acknowledged 159 guest inputs before and 159 after resetting the counters, and passed paused recovery, mutual rematch and Find Next departure. This timing includes the software peer’s ICE gathering and is not a prediction of browser reconnection time.
